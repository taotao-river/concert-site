# 全球演唱会地图

**面向中国（华人）粉丝的欧美明星巡演信息与抢票服务。不卖票、不代订、不碰黄牛。**

> 让每一个对欧美歌手有好感的人，都不再错过 TA 的演唱会。

**当前状态：战略、法律边界、工作规范已定稿；需求尚未验证；产品代码一行没有——而且现在不该写。**

---

## 一、这是门什么生意（诚实版）

| | |
|---|---|
| 需求 | **真实，但小且低频**。跨境看演唱会对个人是 1-2 年一次的决策 |
| 首年收入 | 中位数 **1.5-3 万元**（全年，不是每月） |
| 首年成本 | 1.2-3.6 万元 |
| 现金流转正 | **第 12-18 月** |
| 作为创业项目 | **不成立**——收入上限撑不起一个全职人力 |
| 作为副业 | **成立**——且跨境订阅计费/联盟结算的实操学习价值可能高于财务回报 |

**护城河只有两个：时效性（开票提醒）和人（1v1 服务）。**
不是数据——数据不是壁垒，数据获取权才是风险。
不是攻略文本——发布当天就会被搬运，付费墙拦不住文本。

> ⚠️ 这些数字是 2026-09-08 独立复核后的修正值。此前文档中的「月入 17-20 万」是错误算式（把点击当下单，高估约 68 倍），已作废。详见 [商业化可行性分析（独立复核）](商业化可行性分析_独立复核.md)。

## 二、怎么赚钱

**先卖服务，再卖产品。**

```
1v1 抢票+行程咨询  199-499 元/次   ← 主力，不可复制
单巡演攻略包       39-99 元        ← 把咨询标准化
开票提醒           9.9-29 元/年    ← 可自动化，成本近零
旅行联盟佣金       酒店 4-7%       ← 首年按 0-2000 元/月计
年订阅             199-299 元      ← 已降级，续费率预计 <20%
```

盈亏平衡只需 **1v1 咨询 4-8 单/月**。靠联盟达到平衡需要全站 25-30 万 PV/月——首年不可能。

## 三、现在在哪：第 0 阶段 · 需求验证期

**这一阶段只做两件事：发内容、卖 1v1 咨询。不搭站、不买域名、不写代码。**

| 门禁 | 判据 | 状态 |
|---|---|---|
| H1 需求存在 | 小红书单篇收藏 >500 或累计私信 >20 | ⬜ 未开始 |
| **H2 有支付意愿** | **4 周内 1v1 咨询成交 ≥ 5 单** | ⬜ 未开始 |
| H3 联盟能转化 | 出现 ≥ 1 笔真实佣金入账 | ⬜ 未开始 |

**H2 是唯一的生死线。它不过，后面所有模型都不用算。**

阶段推进规则见 [CLAUDE.md 第 1 节](CLAUDE.md)：H1+H2 通过才进标准化期，H2 稳定复现 3 个月才允许做产品。

## 四、现在该做什么

**下一个动作不是搭站，是选艺人。**

1. **定首批 5-10 个艺人** ← 唯一的阻塞项
   规则见 [CLAUDE.md 第 7 节](CLAUDE.md)：`是否在巡演 × 亚洲可达场次 × 中文热度 ÷ 已有攻略供给`
   **「是否在巡演」是否决项**——不在巡演的顶流产生不了任何交易
   可跑 `scripts/fetch_tours.py` 拿到打分草稿，但「攻略供给」那一列必须人工填
2. **人工核实场次**，对照艺人官网，标来源和核实时间
3. **写内容发小红书**，稿件放 `content/`，规范见 [content/README.md](content/README.md)
4. **第 3 周开始报价收钱**，验证 H2

按周拆解见 [MasterPlan 第 12 节](项目总框架_MasterPlan.md)。

## 六、目录结构

```
.
├── CLAUDE.md              ★ 约束层：规范、口径、红线

│   └── README.md
├── scripts/               数据校验工具 —— 非主数据链路
│   ├── fetch_tours.py     艺人优先级打分，产出 artist_priority.json
```

`database/`、`scripts/`、地图原型是第 0 阶段之前的产物，属**已投入的沉没资产**：可维护、可当工具用，但验证通过前不再往里加功能。精力分配是硬约束：**内容 80% / 私域 15% / 网站 5%**。

- **数据源：艺人官网/官方公告 + 人工录入（首年主链路）**，Ticketmaster Discovery API 仅做交叉校验

> ⚠️ 「数据源全部免费」是错误假设，已修正。Songkick 新 key 基本不发放；Spotify 的

> **判断数据源能不能用，看的是 TOS 允不允许你的商业形态，不是技术上能不能抓。**

## 八、红线速查

❌ 售票、代购、代抢、代订、代收代付 · ❌ 组团收费、打包行程收费
❌ 教脚本/绕验证码/代理 IP 绕地区限制/共享预售码 · ❌ 存艺人图片、搬运官方文案

✅ 明示「不售票、不代订」 · ✅ 联盟链接标注「含推广链接」 · ✅ 每条信息标来源和更新时间
