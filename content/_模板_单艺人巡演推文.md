# 模板 · 单艺人巡演推文

> 复制本文件，重命名为 `艺人slug-巡演名.md`，逐格填。
> **填不出来的格子写「待核实」，不要猜。**（`CLAUDE.md` 第 4 节）

---

## 三种推文类型（同一轮巡演，按顺序发）

| 类型 | 时机 | 长度 | 目的 |
|---|---|---|---|
| **A 官宣速报** | 官宣后 24 小时内 | 短 | 抢时效。晚两天就没人看了 |
| **B 巡演全解** | 官宣后 2-5 天 | 长，主力 | 这是你说的「详细的单独推文」，H1 靠它 |
| **C 单站行程拆解** | 开票前 1-2 周 | 中 | 从 B 衍生，每个亚洲站一条，1v1 咨询的入口 |

**一轮巡演 = 1 条 A + 1 条 B + N 条 C（N = 亚洲站数）。**
一个艺人不是一条推文，是一个系列。这是「不那么简单」的具体做法。

---

# A 型 · 官宣速报

时效性是这条的全部价值，所以只答三件事，其余留给 B。

```
【官宣】<艺人中文名> <巡演名> 公布 <N> 场，亚洲有 <城市列表>

📅 亚洲场次
<城市> <月/日>（星期<X>）
<城市> <月/日>（星期<X>）

⏰ 开票时间（北京时间）
<城市>：<M月D日 HH:MM>  ← 这是重点，别人不换算
预售：<M月D日 HH:MM>

🎫 售票平台：<平台名>

完整场次、预售码怎么拿、内地卡能不能付，
整理在下一条 👉 <引导>

数据来源：<官网链接>｜核实时间：<YYYY-MM-DD>
本账号不售票不代订，仅整理公开信息
```

## 头部信息（自己填，不发出去）

| 字段 | 内容 |
|---|---|
| 艺人 | 中文名 / 英文名 / slug |
| 巡演名 | |

| 核实时间 | YYYY-MM-DD |

## 正文骨架

### 1️⃣ 全部场次（先给亚洲，再给欧美）

> 中国粉丝只关心飞得到的。北美场放最后，一句话带过。

| 城市 | 日期 | 星期 | 场馆 | 状态 |
|---|---|---|---|---|
| | | | | 待开票 / 预售中 / 已开票 / 售罄 |

⚠️ 场馆名写「待核实」也比写错强。

### 2️⃣ 开票时间线（换算成北京时间）— 本条的核心价值

> **绝大多数中文内容不做这一步，这是你最容易建立差异的地方。**
> 海外开票常见为当地时间上午 10:00，但**必须以官方公告为准，不要按惯例推**。

| 环节 | 当地时间 | **北京时间** | 门槛 |
|---|---|---|---|
| 艺人官网/粉丝预售 | | | 需注册 + 抽签码 |
| 信用卡/会员预售 | | | 需指定卡种 |
| 公开开票 | | | 无 |

写清楚**距今还有几天**，并提醒时区换算方向（东南亚/日韩比北京早或持平，欧美是前一天晚上）。

### 3️⃣ 预售码怎么拿（分层写）

> 信息差最大的一环。每一层写：**在哪注册 → 什么时候截止 → 什么时候发码 → 发到哪里**。

- 第一层（艺人官网注册）：
- 第二层（信用卡/电信/会员）：
- 第三层（当地平台会员）：

❌ 红线：只写官方渠道。不写代抢、不写脚本、不写共享码、不写代理 IP 绕地区限制。
（`CLAUDE.md` 第 8 节。传违反平台协议的操作会导致读者被砍单，第一个来找你。）

### 4️⃣ 各站在哪个平台卖 — 第二个真空白

> 亚洲各站的票务平台完全不同，这是中文环境里几乎没人系统整理的部分。
> **下表是常见对应关系，仅作查证起点，每轮巡演都由主办方决定，必须逐站核实官方公告。**

| 地区 | 常见平台 | 本轮实际平台 |
|---|---|---|
| 新加坡 | Ticketmaster SG | 待核实 |
| 日本 | e+ / ぴあ / ローソン | 待核实 |
| 韩国 | Interpark / Yes24 | 待核实 |
| 中国香港 | Cityline / URBTIX | 待核实 |
| 泰国 | ThaiTicketMajor | 待核实 |
| 马来西亚 | 主办方自有站 | 待核实 |
| 北美/英国 | Ticketmaster / AXS | 待核实 |

每站附**该场次的直达购票链接**，不要只放平台首页。

### 5️⃣ 票价与支付（框架给到，细节留给咨询）

| 档位 | 当地货币 | 约合人民币 |
|---|---|---|

- 汇率标注取用日期
- 内地卡可用性：待核实 → 常见问题是 3D 验证、地区风控、账单地址
- **砍单风险提示**：一句话点到，展开留给 1v1

### 6️⃣ 签证与提前量（挂到具体场次日期上）

> ⚠️ **免签政策变动频繁，每次发布前必须重新核实，不要沿用上一篇。**

| 目的地 | 中国护照要求 | 建议提前 | 核实日期 |
|---|---|---|---|
| | 待核实 | | |

写法：不写「新加坡免签」，写「按 <日期> 查询，<目的地> 对中国护照 <政策>，距 <场次日期> 还有 <N> 天，建议 <提前量>」。

### 7️⃣ 总花费框架（不给精确数，给结构）

```
门票 + 机票 + 住宿(N晚) + 当地交通 + 餐饮 = 区间
```

给区间和影响因素，不给「就是 X 元」。精确拆解是 C 型和 1v1 的内容。

### 8️⃣ 结尾三件套（每篇都要有）

```
数据来源：<一手链接>
核实时间：<YYYY-MM-DD>
本账号不售票、不代订，仅整理公开信息，请以官方公告为准
```

# C 型 · 单站行程拆解

每个亚洲站一条。B 型回答「能不能抢到」，C 型回答「值不值得去、怎么去」。

- 该场次的完整时间线（落地 → 入场 → 散场 → 返程）
- 场馆周边住宿区域怎么选（**含推广链接**要标注）
- 散场交通（大型场馆散场是真痛点）
- 该城市的 2-3 天顺带安排
- 结尾：**「你的具体情况（几个人、几天、预算多少）可以私信」← 1v1 入口**

- [ ] 每站有直达购票链接，不是平台首页
- [ ] 签证信息是**本次重新核实**的，不是抄上一篇

- [ ] 推广链接已标注
- [ ] 填不出来的地方写的是「待核实」，不是猜的值

## 平台适配

骨架不变，包装不同：

- **小红书（主）**：首图做成信息图（场次表 / 开票时间线），正文承载 1-4 节，5-8 节压缩
- **微博**：正文短，把 B 型全文做成一张长图
- **X**：只发英文场次和时间，不做中文攻略（受众不同）
