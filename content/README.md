# content/ · 内容稿件

**这是第 0 阶段的主战场。**按 `CLAUDE.md` 第 1 节，现阶段精力分配是 内容 80% / 私域 15% / 网站 5%。

## 命名约定

```
艺人-主题.md          例：the-weeknd-亚洲场次汇总.md
平台-主题.md          例：ticketmaster-注册全流程.md
城市-行程.md          例：singapore-观演行程模板.md
```

艺人用 slug（与 `database/seed.sql` 的 `artists.slug` 一致），主题用中文。

## 每篇稿件的头部必须写清

```markdown
---
类型: 巡演场次 / 抢票攻略 / 行程指南
艺人: the-weeknd
平台: 小红书
状态: 草稿 / 已发布
数据来源: https://...（官网或官方公告链接）
核实时间: 2026-09-08
---
```

**没有来源和核实时间的稿件不发布。**信息错一次，付费用户就没了（`CLAUDE.md` 第 4 节）。

## 内容单元：一个艺人一个系列，不是一条

模板见 [`_模板_单艺人巡演推文.md`](_模板_单艺人巡演推文.md)。一轮巡演拆成三种推文：

| 类型 | 时机 | 目的 |
|---|---|---|
| **A 官宣速报** | 官宣 24h 内 | 抢时效，只答场次/北京时间/平台三件事 |
| **B 巡演全解** | 官宣后 2-5 天 | **主力**，H1 靠它 |
| **C 单站行程拆解** | 开票前 1-2 周 | 每个亚洲站一条，1v1 咨询的入口 |

**一轮巡演 = 1 条 A + 1 条 B + N 条 C**（N = 亚洲站数）。

### 差异化在哪

「XX 要开巡演了」这条信息本身没有差异化，微博粉丝站比你快。价值在于回答中文环境查不到的部分，按信息差从大到小：

1. **开票时间换算成北京时间** —— 几乎没人做，却是最容易错过的一步
2. **各站在哪个平台卖** —— 亚洲各站平台完全不同，中文环境几乎空白
3. **预售码分层与各层时间** —— 信息差最大
4. 完整场次（尤其亚洲站）
5. 内地卡支付与砍单 / 票价换算 / 签证提前量 / 花费拆解 —— 免费给框架，细节留给 1v1

前 4 项是免费内容的主体，第 5 项给到框架即可。这样内容和变现是同一条链，不是两件事。

完整 30 个选题库见《香港身份运营方案》9.2 节。
